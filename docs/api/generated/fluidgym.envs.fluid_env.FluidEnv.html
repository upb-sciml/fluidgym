FluidEnv

class fluidgym.envs.fluid_env.FluidEnv(adaptive_cfl: float, dt: float, step_length: float, episode_length: int, ndims: int, use_marl: bool, dtype: dtype = torch.float32, cuda_device: device | None = None, cpu_device: device | None = None, load_initial_domain: bool = True, load_domain_statistics: bool = True, randomize_initial_state: bool = True, enable_actions: bool = True, differentiable: bool = False, advection_tol: phipict.solvers.tolerance.SolverTolerance = None, pressure_tol: phipict.solvers.tolerance.SolverTolerance = None, pressure_tol_intermediate: phipict.solvers.tolerance.SolverTolerance = None, pressure_warm_start: bool = False, linear_solve_max_iter: int | None = None, exclude_advection_solve_gradients: bool | None = None, exclude_pressure_solve_gradients: bool | None = None, exclude_pressure_gradient_adjoint: bool | None = None, n_envs: int | None = None)[source]

Bases: ABC, FluidEnvLike

Abstract base class for FluidGym environments.

It provides common functionality for all FluidGym environments, such as managing the simulation, rendering, and saving/loading initial domains.

Batched environments. With n_envs=E the environment runs E copies of itself in one batched simulation on its GPU: same grid, boundaries and sparsity patterns, own states, actions, observations and rewards. The API then carries a leading env dim everywhere: actions [E, *action] ([E, A, *action] in MARL), observations [E, *obs], rewards [E] ([E, A]), terminated and truncated bool tensors [E] and info values [E]. With the default n_envs=None it is a single environment without that dim, exactly as before. All environments share the episode length and, with adaptive substepping, the time step (set by the fastest environment).

Internally, every environment works with the leading env dim regardless of n_envs (E = 1 for a single environment): block fields are [E, ...] and _apply_action(), _get_global_obs(), _advance_impl() and _finish_step() take and return per-environment tensors. The base class removes the env dim for a single environment.

Raises:

  • RuntimeError – If CUDA is not available.

  • ValueError – If ndims is not 2 or 3.

Notes

The environment must be reset before calling step(). The initial domain must be generated by calling init() before using the environment for training or evaluation. The initial domain is saved to disk when init() is called, and loaded when reset() is called.

property adjoint_rtol: float | None

Relative residual every adjoint (backward) linear solve is held to.

Each adjoint solve stops on ||r|| < rtol * ||g||, with g its incoming gradient. The tolerance is proportional to g, so the gradient does not depend on the scale of the loss: the reward scale, the natural magnitude of the reward or the adjoint decaying along the rollout. None (the default) holds each adjoint solve to the rtol of its forward solve, e.g. pressure_tol, and a forward solve with an absolute tolerance to phipict.solvers.tolerance.ADJOINT_RTOL_FALLBACK. A float overrides this for every solve.

This is a process-wide solver setting (phipict.solvers.tolerance.set_adjoint_rtol()), shared by every env in the process; the last one set wins.

property bptt_carry_spill_dir: str | None

Directory to write checkpoint carries into, instead of host RAM.

At a long horizon the carry is what host memory runs out of: it is one state snapshot per step. Note /tmp and /dev/shm are usually tmpfs, i.e. RAM.

property bptt_checkpoint: bool

Run each env step as an activation checkpoint (differentiable BPTT).

The step is run under no_grad during the rollout and replayed under enable_grad in backward, so only one step’s activations are ever live. This is what makes GPU peak independent of the rollout length; offloading the tape alone leaves a residue per PISO step that caps the horizon.

Costs one extra forward per step, plus one carry per step (see bptt_offload_device / bptt_carry_spill_dir). Only meaningful on a differentiable environment.

property bptt_offload_device: device | None

Where checkpoint carries are parked (None = keep on the GPU).

property bptt_segment_size: int

PISO steps per checkpoint segment (0 = one segment per env step).
